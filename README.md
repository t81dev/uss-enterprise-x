# USS Enterprise X — Project Occam-7

**Repository:** `uss-enterprise-x`  
**Internal codename:** **Project Occam-7**  
**Design state:** v1 conceptual architecture

A speculative first-principles engineering program for rebuilding the idea of the **USS Enterprise** as an actual deep-space vehicle rather than a television-era spacecraft.

> **Core thesis:** The Enterprise should be designed from mission, physics, manufacturability, reliability, economics, and human survivability outward — not from the familiar silhouette inward.

This project deliberately uses a **fictionalized Musk-inspired engineering voice** in selected design memos. Those memos are creative artifacts, not statements of Elon Musk's actual views, plans, or technical positions.

## Non-negotiable design rules

1. **Mission before geometry.** Start with what the ship must accomplish.
2. **First principles before inheritance.** Every inherited convention is a hypothesis to be challenged.
3. **Mass is a budget.** Every kilogram must earn its place.
4. **Power creates heat.** No major energy system is accepted without a credible thermal path.
5. **Reusability is mandatory.** People do not ride disposable hardware.
6. **Autonomy is structural.** Deep-space communication latency makes local competence mandatory.
7. **Manufacturing is part of the design.** If a subsystem cannot be built, inspected, repaired, or replaced economically, it is unfinished.
8. **Failure is information.** Hardware iteration beats perfect-looking paperwork.
9. **Physics has veto power.** Speculative technologies are isolated, labeled, and given explicit evidence thresholds.
10. **Human survivability outranks aesthetics.** The ship is a habitat, laboratory, machine shop, and emergency shelter before it is an icon.

## Reality classification

Each major concept is tagged conceptually as one of:

- **Plausible path** — grounded in known physics and an identifiable engineering development path.
- **Frontier** — physically allowed in principle but far beyond present capabilities.
- **Speculative** — depends on unresolved science or breakthroughs that do not currently exist.
- **Fictional** — retained because it is part of the Enterprise design language, not because it is currently credible engineering.

## Version philosophy

**X is a variable.** It means the architecture is intentionally allowed to change.

The goal of v1 is not to produce a finished starship. The goal is to identify which parts of the Enterprise concept survive aggressive engineering criticism and which parts collapse under it.

## Immediate question

> **What is the smallest reusable, self-sufficient deep-space vehicle that can prove the Enterprise mission without pretending that unresolved physics has already been solved?**
